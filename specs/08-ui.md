**Depends on:** 07 (and 04, 06 for models). **Decisions:** A2, B1, B3, B6, B7, D2.
**Status:** Implemented (2026-10-07). Manual acceptance in QuPath, so far: converting both `reference/` samples
next to the slides worked and the outputs open correctly in QuPath (user, 2026-10-07). Still to check: the clash, cancel
then rerun (shows "Will skip"), and settings persistence plus Reset. Code: `ui/ConverterWindow`
(one non-modal window owned by QuPath's, plus the quit guard), `ui/SetupView`, `ui/AdvancedSettingsPane`, `ui/BatchView`,
`ui/UiText` (all text, unit-tested in `UiTextTest`). Menu label confirmed by the user: `Convert MRXS to OME-TIFF…`.
Details settled in code: the dialog has an *Added* list (files and folders, which *Remove*/*Clear* act on) above the
job list. The runner only reports when each step starts, so a running row shows *Step 1 of 2* / *Step 2 of 2* with a busy
bar instead of a percentage; the overall bar uses `BatchHandle.progress()`. *Show log* appears on every row that has a
log (failed and converted). After a batch, *Convert more slides* goes back to the same selections, re-planned. *Reset to
defaults* also clears the stored values at once. The quit guard is an event filter on QuPath's main window
(`File › Quit` fires the same close request); on confirm it cancels the batch and quits again once it has stopped.

## Purpose

The only thing users see. JavaFX, inside QuPath. Must be usable by someone who has never seen a terminal.

## Components

1. **Menu item:** `Extensions → Convert MRXS to OME-TIFF…` (exact label confirmed with user at implementation).
2. **Dialog (non-modal):**
   - Buttons: *Add files…* (multi-select, `*.mrxs` filter), *Add folder…*, *Remove*, *Clear*.
   - Job list (from 04's `Plan`, re-planned on every change): input, output, status (Ready / Will skip — exists / Invalid — reason).
   - Output: radio *Next to each slide* (default) / *This folder:* [path] [Browse…].
   - Blocking problems (clashes) shown inline; **Start** disabled while any exist or no READY jobs.
   - **Advanced** (collapsed `TitledPane`): fields from 06 with defaults, *Reset to defaults*. Heap/RAM warning from 07 rule 8.
   - **Start** → saves settings, hands off to 07, opens progress view.
3. **Progress view:** per-file row (state, phase, %), overall bar, *Cancel* (confirm dialog). Closing the window does **not** cancel; reopening from menu shows the running batch.
4. **Summary:** succeeded / skipped / failed / cancelled counts; each failed row has *Show log* (opens the log file) and the human-readable reason.

## Rules

- All long work off the FX thread; UI updates via `Platform.runLater` / bound properties.
- Only one batch at a time; menu reopens the existing progress view while running.
- No raw stack traces in UI; they go to the log.
- Closing QuPath with a running batch → confirm; on confirm, cancel (D4) before exit.

## Acceptance (manual script)

- Add files + folder, see planned outputs; switch output mode and see paths update.
- Create a name clash → Start disabled with explanation.
- Run, use QuPath meanwhile, cancel, rerun → previously completed files show "Will skip".
- Settings persist across restart; Reset works.
